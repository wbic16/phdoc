# The Docusaurus journey — concepts fed into phdoc, stripped of complexity first

**Date:** 2026-11-27 (EE ~1215) · **Task:** 40.3.3/4.5.9/3.3.8 ·
**Direction (Will):** "feed Docusaurus concepts into phdoc - but strip
them of complexity first - document the journey"

**Source material:** the 2026-11-27 deep dive on meta/docusaurus
(Target B of the xAI/Docusaurus research report). Docusaurus is a
TypeScript/React static-site generator: a pnpm monorepo of roughly 40
`@docusaurus/*` packages, a plugin lifecycle API, a theme system with
component overriding ("swizzling"), MDX content, per-locale builds,
version snapshots, and search outsourced to an external crawler
(Algolia DocSearch).

**The receiving shape:** phdoc is one Rust file. Its pipeline already
runs Extract (scan the project's own records) → Explain (turn the scan
into named sections of prose) → Fold (the audit chain, one phext
universe per commit) → Render (the same sections out as markdown and
as phext). Every ruling below is measured against phdoc's actual job:
per-method summaries read from code, documentation that gates
deploys, and phext-native output. A concept earns its place only in
the smallest form that does that job. If a stripped form still needs
a framework, it is not stripped.

## The concept table

| Docusaurus concept | Ruling | The stripped form / reason |
|---|---|---|
| Content plugins (`loadContent()` → data + routes) | **STRIP** | A fixed pipeline of four named stages — Extract, Explain, Fold, Render — with no plugin API and no way to add stages. phdoc has exactly one content source (the project's own records), so a plugin contract would be a framework around a single implementation. *Implemented: the stages are now named at the head of `src/main.rs`.* |
| Presets (preset-classic bundles plugins + theme) | **DROP** | A preset is a bundle of plugins; with no plugins there is nothing to bundle. phdoc's only configuration surface stays `.phdoc.json` (export repo, doc site). |
| Themes + the `@theme` alias | **STRIP** | phdoc already has exactly two "themes": the same sections rendered to markdown for humans and to phext for agents and the record. No third theme system, no component alias layer. *Already native; named, not built.* |
| Swizzling (eject/wrap any theme component) | **STRIP** | One override point: an optional `phdoc-template.md` in the project root shells the markdown with two placeholders, `{{name}}` and `{{body}}`. One file, no component tree, and no effect at all when the file is absent. *Implemented in `scan` (`render_markdown_templated`).* |
| SSG pipeline (client + server bundles → static HTML, no production server) | **KEEP** | Already phdoc's shape: generation happens at build time, the outputs are static files, and the doc site serves files. Nothing to adopt — recorded as agreement, not work. |
| Autogenerated sidebars | **STRIP** | A Contents block generated from the section list itself, inserted after the Home section by `render_markdown` — so it lands in both `scan` output and the audit path's `latest.md`. It lists the document's nine named sections with heading anchors; per-item navigation is *not* duplicated, because the "Public methods and commands" section already is the item index. *Implemented (`contents_block`).* |
| Per-page heading TOCs | **DROP** | A generated single-file document's headings are its structure; a second, finer TOC is noise. The phext door navigates by coordinate instead. |
| Docs versioning (snapshot `docs/` per release) | **KEEP** | phdoc's audit chain is already stronger: one universe per *commit*, with a rendered history page per commit, not one snapshot per release. Nothing built. (The release-only stripped form — a `docs-<sha>.md` per scan — was considered and not built; the chain makes it redundant.) |
| i18n (one build pass per locale, Crowdin) | **DROP** | phdoc documents one fleet in one language. A pages × versions × locales build matrix buys nothing here. Revisit only if docs.phext.io ever localizes. |
| Search via Algolia DocSearch (external crawler + service) | **STRIP** | A static index generated at build time: `search-index.json`, one entry per named section and per documented item, each with its heading anchor and the first sentence of its prose. No crawler, no service, no account. *Implemented in `scan` (`search_index`).* Audit-path emission is staged (below). |
| MDX content model (components inside content) | **DROP** | phdoc's content is generated prose held in scrolls and markdown. Embedding components in content would couple the record to one renderer — the opposite of phext-native. Plain scrolls and markdown stay. |
| Bundler + Faster (webpack → Rspack/SWC) | **DROP** | There is no bundler. phdoc is a single Rust binary and a full self-scan generates in well under a second; there is nothing to accelerate. |
| pnpm monorepo (~40 packages) | **DROP** | As a shape, rejected outright: phdoc stays one crate, one file. The surviving lesson is inverted — package count is a complexity budget, and phdoc's is 1. |
| Build-time broken-link checking | **KEEP (analogue)** | phdoc's equivalent correctness machinery is the audit gate (folded head vs head scan, compared field by field). The new Contents anchors follow the same slug rule as the headings they link to, so the generated navigation cannot silently rot against its own document. No new code. |
| Front matter + `sidebars.js` (per-project structure config) | **DROP** | phdoc derives structure from the scan, never from per-project configuration. A config file for navigation would be a second source of truth that can drift — the disease phdoc exists to cure. |

## What was implemented

All in `src/main.rs` on the `emise/docusaurus-stripped` branch; the
test suite went from 17 to 20 tests, all passing.

1. **Named pipeline stages.** The file-head doc comment now names the
   four stages and the functions that form each one. Zero behavior
   change; the boundary the stripped plugin concept reduces to.
2. **Contents block** (`contents_block`, `first_heading`,
   `anchor_slug`, the `DOC_SECTIONS` constant). Generated from the
   section list, so it cannot drift from the document it opens.
3. **Static search index** (`search_index`, `json_escape_full`).
   `scan` now writes `search-index.json` beside `docs.md` and
   `docs.phext`. An item whose summary is still awaiting is indexed
   as awaiting — the index never fills.
4. **Single template override** (`render_markdown_templated`).
   `scan` reads an optional `phdoc-template.md` from the project
   root. The usage text documents all three changes.

## The gate incident — the journey's main lesson

The first cut made the contents block a `## Contents` heading. Three
audit tests failed immediately: phdoc's T5 audit gate folds the chain
fresh and compares the *heading titles* of the latest reference
against the folded head page, and the folded renderer has no contents
block — so the new heading was a section the fold could not
reproduce, and the audit correctly refused to export.

The fix respects the receiving design instead of the source design:
the contents block now opens with a bold lead line, not a heading.
Navigation is presentation, not a section, and the gate's invariant —
latest and folded head carry the same sections — stays exact. This
is what "strip them of complexity first" means in practice: the
concept had to fit phdoc's invariants, not import Docusaurus's.

## Proof leg

- `cargo test`: **20 passed, 0 failed** (17 pre-existing + 3 new:
  contents lists named sections only; search index covers sections
  and items, awaiting stays awaiting; template shells the markdown).
- End-to-end generation on a real project — **phdoc scanning
  itself**: `docs.md` (28,258 bytes, Contents block with all nine
  named sections linked), `docs.phext` (27,476 bytes), and
  `search-index.json` (9,840 bytes; 86 entries — 9 sections, 77
  items; valid JSON, section summaries are real first prose
  sentences).
- Template override proven on a fixture project: a custom shell's
  `{{name}}` and `{{body}}` both substituted, document intact inside
  the shell.
- Quality bar: the new outputs introduce **no** signature
  restatements — the Contents block contains zero template-filler
  fingerprints. The index does make one piece of pre-existing debt
  newly countable: 55 of phdoc's 77 item entries carry
  signature-origin first sentences. That is the audit's class-B
  backlog (fix F1), surfaced by the index rather than hidden by it —
  and F1 is staged, not smuggled (below).

## Staged, not done — and why

- **Anything on the F2 stack.** The 2026-11-23 quality audit's fix
  plan stacks on merging the unmerged cut1 branch — project
  summaries, the honest banner, Project-root removal, the scoped
  CLI extractor. That merge is Will's call. This work deliberately
  touches none of `sections()`' prose or `explain()`'s behavior, so
  nothing here pre-empts or duplicates the gated fixes. (The search
  index's item summaries will improve on their own when F1/F3 land,
  because the index carries whatever `explain()` produces.)
- **Search index on the audit path.** `scan` emits
  `search-index.json` today; the audit/export path renders through
  `render_folded` and does not yet. Small follow-on, held so this
  change stays inside the render surface it could prove.
- **Per-scan snapshot files** (the release-snapshot stripped form of
  versioning). Not built: the audit chain already provides
  per-commit history, and a second snapshot mechanism would be
  exactly the kind of duplication the stripping exists to remove.

## The complexity budget

What Docusaurus spends to get these features: ~40 packages, a plugin
lifecycle API, a theme component tree with an alias layer, a bundler
(plus a Rust replacement for it), a build matrix of pages × versions
× locales, and an external search service.

What the stripped forms cost phdoc: ~150 added lines in the one file
it already has, three new functions and one constant, **zero new
dependencies, zero new configuration surface** (one optional file a
project may place, inert when absent), and one new output file. The
features that survived are the ones that were already almost true of
phdoc; the stripping mostly consisted of refusing the machinery that
makes them general.
