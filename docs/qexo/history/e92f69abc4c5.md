## function — serialize

Found in src/phext.rs at line 129.

Signature: `pub fn serialize(&self) -> String {`

What it does: Serialize canonically: ascending coordinates, walking the dead-reckoning path from each scroll to the next. A single delimiter advances ONE component by ONE — so reaching a distant address takes a STACK of delimiters (component by component, most significant first, each emission resetting the less-significant components to 1), with no text between them. That is how CYOA's sparse landscape is actually laid down (a scroll at 13.13.13 is reached by climbing, not by one jump), and it is the only serialization parse can read back faithfully: an earlier form of this function emitted just the highest changed component's delimiter, which made every jump of more than 1 in any component land at the wrong address on re-read — patterned homeland addresses (2.2.2/2.2.2/2.2.2 and kin) were unrepresentable. Found by the v1.0 battery, 2026-11-12: records a command had just written could not be found by the next process.
